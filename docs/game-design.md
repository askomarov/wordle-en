# Game Design Spec — agent-game

**Роль документа:** продуктовая спецификация игровой механики.  
**Жанр:** word puzzle (угадай слово).  
**Платформа (целевая):** веб (Nuxt).  
**Аудитория (v1):** англоязычная.  
**Язык продукта (v1):** английский — UI-тексты и загаданные/вводимые слова.

---

## 1. Концепция

Игрок угадывает одно загаданное **английское** слово из **5 букв** за **5 попыток**.

После каждой попытки система оценивает каждую букву и подсвечивает клетку и клавишу:

| Состояние | Смысл |
|-----------|--------|
| **correct** | буква есть в слове и стоит на верной позиции |
| **present** | буква есть в слове, но на другой позиции |
| **absent** | буквы нет в загаданном слове |

Игра намеренно простая: один экран, без уровней, без аккаунтов, без рейтинга в v1.

---

## 2. Правила игры

### 2.1. Слово

- Длина слова: ровно **5 букв**.
- Алфавит v1: **латиница A–Z** (английский).
- Слово загадывается из словаря **решений** (`solutions`) — английские слова.
- Игрок может вводить только слова из словаря **допустимых ходов** (`validGuesses`) — английские слова.
- `solutions ⊆ validGuesses`.
- Слова нормализуются к **UPPERCASE** для сравнения и хранения в рантайме.
- В v1: только буквы A–Z, без дефисов, пробелов, апострофов, цифр.
- Повторяющиеся буквы допустимы (например, `APPLE`).

### 2.2. Попытки

- Максимум попыток: **5**.
- Одна попытка = одно полностью введённое и подтверждённое слово из 5 букв.
- Пустые клетки до подтверждения попытки не оцениваются.
- После оценки попытки строка становится неизменяемой.

### 2.3. Оценка букв (ключ механики)

Оценка выполняется **по позициям**, с учётом кратности букв.

Алгоритм (для одной попытки):

1. Сначала пометить все точные совпадения (`correct`), «зарезервировав» эти вхождения в загаданном слове.
2. Затем для оставшихся букв попытки:
   - если такая буква ещё есть среди незарезервированных в загаданном слове → `present` и зарезервировать одно вхождение;
   - иначе → `absent`.

**Пример:** загадано `APPLE`, ввод `PAPAL`:

Загадано: `A P P L E`  
Ввод:     `P A P A L`

1. Exact-совпадений нет.
2. Идём слева направо по незакрытым буквам ввода, резервируя вхождения в ответе:
   - `P` → `present` (есть P в ответе)
   - `A` → `present` (есть A)
   - `P` → `present` (вторая P в ответе)
   - `A` → `absent` (A уже зарезервирована)
   - `L` → `present` (есть L)

Итог: `present, present, present, absent, present`.

**Ещё пример (лишний повтор):** загадано `APPLE`, ввод `PPPPP`:

1. Exact: pos2 `P`=P → correct; pos3 `P`=P → correct.
2. Незарезервированных P в ответе больше нет.
3. Остальные три `P` → `absent`.

Итог: `absent, correct, correct, absent, absent`.

Это критично: лишние повторы буквы не получают `present`, если все вхождения уже закрыты.

### 2.4. Что запрещено

- Ввод слова короче/длиннее 5 букв.
- Подтверждение неполного слова.
- Подтверждение слова вне `validGuesses`.
- Изменение уже отправленных строк.
- Продолжение ввода после победы/поражения (до New Game).

## 3. Игровой цикл

```
[Start / New Game]
        ↓
  Pick word from solutions
  Reset board, keyboard, status
        ↓
  [Waiting for input]
        ↓
  Player types letters → [Editing row]
        ↓
  Player presses Enter
        ↓
  Validation ──no──→ feedback (shake + toast) → back to input
        ↓ yes
  Score letters → reveal animation
        ↓
  Update keyboard key states
        ↓
  Win? ──yes──→ [Won]
        ↓ no
  Out of guesses? ──yes──→ [Lost]
        ↓ no
  Next row → [Waiting for input]
```

Один раунд = от загадывания слова до win/lose.  
**New Game** стартует новый раунд с новым словом.

---

## 4. Обработка ввода

### 4.1. Источники ввода

1. Физическая клавиатура.
2. Экранная клавиатура (клик/тап).

Оба источника пишут в одну и ту же модель текущей строки.

### 4.2. Действия

| Действие | Условие | Эффект |
|----------|---------|--------|
| **Letter** | игра активна; в текущей строке < 5 букв | добавить букву в конец |
| **Backspace** | игра активна; в строке ≥ 1 буква | удалить последнюю букву |
| **Enter** | игра активна | попытка подтвердить слово |
| **New Game** | всегда (после старта UI) | начать новый раунд |

Игнор:

- символы вне A–Z;
- ввод, когда строка уже полная;
- Backspace на пустой строке;
- любой игровой ввод в статусах `won` / `lost`;
- модификаторы/служебные клавиши (кроме Backspace/Enter).

### 4.3. Подтверждение (Enter)

Порядок проверок:

1. Длина ≠ 5 → toast: `Not enough letters`
2. Слово ∉ `validGuesses` → toast: `Not in word list`
3. Иначе — принять попытку, запустить оценку.

Сообщения краткие, исчезают через ~1.5–2 с (или при следующем успешном действии).

### 4.4. Фокус и доступность (v1)

- Игровое поле принимает клавиатурный ввод без обязательного клика в input (глобальный key listener на экране игры).
- Экранная клавиатура обязательна для мобильных.
- В v1 можно без полноценного screen-reader UX, но кнопки клавиатуры должны быть нажимаемыми и с понятными подписями (`Enter`, `Backspace` / иконка ⌫).

---

## 5. Поведение клавиатуры

### 5.1. Раскладка (QWERTY, v1)

```
Q W E R T Y U I O P
 A S D F G H J K L
  Z X C V B N M  ⌫
        ENTER
```

26 букв A–Z + `ENTER` + `⌫`. Без локальных раскладок в v1.

### 5.2. Состояния клавиш

У каждой буквенной клавиши есть агрегированный статус:

| Приоритет (выше важнее) | Статус | UI |
|-------------------------|--------|-----|
| 3 | `correct` | зелёный |
| 2 | `present` | жёлтый/янтарный |
| 1 | `absent` | тёмный/приглушённый |
| 0 | `unused` | нейтральный |

Правило обновления: статус клавиши **только усиливается**, не ослабевает.

Примеры:

- было `absent`, пришло `present` → `present`;
- было `present`, пришло `correct` → `correct`;
- было `correct`, пришло `present` → остаётся `correct`.

`ENTER` и `⌫` статусов букв не имеют.

### 5.3. Поведение кнопок

- Press feedback (короткий pressed-state).
- Disabled visually/логически в `won`/`lost` для букв / `⌫` / `ENTER` (кроме кнопки New Game вне клавиатуры).
- Повторный быстрый тап не должен ломать состояние строки.

---

## 6. Состояния букв и клеток

### 6.1. Клетка (tile)

| Состояние | Когда | Визуал |
|-----------|-------|--------|
| `empty` | нет буквы | пустой контур |
| `filled` | буква введена, строка ещё не отправлена | буква + более жирный контур |
| `correct` | после оценки | зелёный фон |
| `present` | после оценки | жёлтый/янтарный фон |
| `absent` | после оценки | серый/тёмный фон |

Transient UI (не игровая логика):

- `invalid-row` — короткий shake текущей строки при ошибке валидации;
- `reveal` — последовательное раскрытие клеток после успешного Enter (слева направо, ~100–150 мс шаг).

### 6.2. Строка (row)

| Состояние | Описание |
|-----------|----------|
| `upcoming` | будущая попытка, пустая |
| `active` | текущий ввод |
| `submitted` | оценена, заблокирована |
| `locked` | после конца игры неактивные пустые строки |

Доска: **5 строк × 5 клеток**.

### 6.3. Цветовая семантика

- `correct` — right spot.
- `present` — in word, wrong spot.
- `absent` — not in word.

Цвета должны сохранять читаемость буквы (контраст). Точные токены — в UI/design tokens.

---

## 7. Победа

**Условие:** после оценки попытки все 5 клеток строки в статусе `correct`  
(эквивалентно: guess === answer).

**Эффекты:**

1. Статус раунда → `won`.
2. Ввод блокируется.
3. Toast победы (по номеру попытки):

| Attempt | Copy (v1) |
|---------|-----------|
| 1 | `Genius` |
| 2 | `Magnificent` |
| 3 | `Impressive` |
| 4 | `Splendid` |
| 5 | `Phew` |

4. Опционально лёгкая анимация на победной строке.
5. Доступна кнопка `New Game`.

Ответ при победе дополнительно показывать не обязательно (слово и так на доске); для симметрии с поражением можно продублировать в status line.

---

## 8. Поражение

**Условие:** 5-я попытка оценена и слово не угадано.

**Эффекты:**

1. Статус раунда → `lost`.
2. Ввод блокируется.
3. Toast/status: `The word was {ANSWER}` (ANSWER в UPPERCASE).
4. Доступна `New Game`.

Игрок должен однозначно увидеть ответ.

---

## 9. New Game

### 9.1. Триггеры

- Кнопка `New Game` / `Play again`.
- (v2) хоткей — не обязательно в v1.

### 9.2. Поведение

1. Выбрать новое слово из `solutions`.
2. **Рекомендация v1:** не повторять предыдущее слово подряд, если в словаре > 1.
3. Очистить доску (все клетки `empty`).
4. Сбросить клавиши в `unused`.
5. Статус → `playing`.
6. Активная строка = 0.
7. Скрыть win/lose сообщения.

### 9.3. Выбор слова

- v1: равномерный random из `solutions` (с анти-повтором подряд).
- Режим «word of the day» — не в v1 (можно в v2).

---

## 10. Основные UI-состояния

### 10.1. Состояния экрана/раунда

| ID | Описание | Ввод | CTA |
|----|----------|------|-----|
| `playing` | обычная игра | да | — |
| `won` | победа | нет | `New Game` |
| `lost` | поражение | нет | `New Game` |

UI-флаги:

| Флаг | Назначение |
|------|------------|
| `toast` | короткое сообщение (ошибка / победа / ответ) |
| `revealing` | анимация оценки; ввод блокировать до конца reveal |
| `boardInvalidPulse` | shake строки |

Во время `revealing` Enter/буквы/⌫ игнорируются.

### 10.2. Каркас экрана

1. Title / game name (EN).
2. Board 5×5.
3. Toast/status над или под доской.
4. On-screen keyboard.
5. Кнопка `New Game` (особенно явно в `won`/`lost`).

Без сложных панелей и настроек в v1 (кроме лёгкого How to Play).

### 10.3. Онбординг

Первый заход (local flag):

- overlay `How to Play` с 3 примерами: correct / present / absent;
- кнопка `Got it`.

Повторно — по `?` в шапке.

**Пример copy для How to Play (v1):**

- `Guess the 5-letter word in 5 tries.`
- `Green` — right letter, right spot.
- `Orange` — right letter, wrong spot.
- `Gray` — letter not in the word.

Все UI-строки продукта — на английском.

## 11. Словари и контент

### 11.1. Два списка

| Список | Назначение | Требования |
|--------|------------|------------|
| `solutions` | загадываемые слова | частые английские слова, «честные», без редкой грязи |
| `validGuesses` | что можно ввести | шире solutions; валидные английские 5-letter words |

### 11.2. Политика контента (v1)

- Без обсценных/оскорбительных слов в `solutions` (validGuesses можно чуть шире, но базовый фильтр желателен).
- Предпочтительно common nouns / familiar vocabulary для solutions.
- Без proper nouns, аббревиатур и сленга в solutions (допустимо точечно в validGuesses при необходимости).
- Американский английский как дефолт орфографии словаря (фиксируем один вариант: `COLOR` vs `COLOUR` — не смешивать в solutions; рекомендация: **US English**).

Объём: для прототипа — небольшой quality set; для релиза — сотни+ solutions и расширенный valid list.

## 12. Edge cases

### 12.1. Повторяющиеся буквы

- См. §2.3 — оценка с резервированием вхождений.
- Клавиша получает максимальный статус среди всех оценок этой буквы в истории раунда.

### 12.2. Одинаковый guess повторно

- Если слово ∈ `validGuesses`, повтор **разрешён** в v1.
- v2-альтернатива: запрет с toast `Already tried`.

### 12.3. Регистр и раскладка

- `a` и `A` эквивалентны.
- Не-латиница игнорируется (кириллица и пр. не вводятся).
- Нет автомаппинга раскладок.

### 12.4. UK vs US spelling

- Словари в одном орфографическом стандарте (**US**).
- Игрок с UK-вариантом, которого нет в list → `Not in word list` (ожидаемо).

### 12.5. Быстрый ввод во время анимации

- Пока `revealing === true`, ввод дропается.
- После reveal: win/lose или следующая строка.

### 12.6. Спам Enter

- На неполном/невалидном слове — повторный toast, попытка не тратится.
- После конца игры — no-op.

### 12.7. Победа на последней попытке

- Это **победа**, не поражение.
- Проверка win раньше проверки «попытки кончились».

### 12.8. Пустой словарь / битые данные

- Пустой `solutions` → не стартовать раунд, показать dev/error state.
- Слова ≠ 5 букв или с non A–Z — отфильтровать на загрузке.

### 12.9. Мобильный UX

- Не открывать системную клавиатуру (нет focusable text input, либо readonly + своя клавиатура).
- Кнопки достаточны для тапа.
- Toast не перекрывает доску критично.

### 12.10. Обновление страницы

- v1: персист не обязателен; refresh = потеря раунда OK.
- v2: localStorage (answer, guesses, status).

### 12.11. Доступность цвета

- В v1 цвет — primary signal; в v2 можно паттерны/иконки для color vision deficiency.

### 12.12. Контраст present vs correct

- Статусы должны однозначно различаться визуально.

---

## 13. Нефункциональные требования (кратко)

- Отклик на keypress: <50 мс до обновления UI-модели.
- Reveal-анимация без заметных лагов.
- После How to Play игра понятна за ≤10 секунд.

---

## 14. Out of scope (v1)

- Word of the day / streaks / share-to-social.
- Аккаунты, лидерборды, мультиплеер.
- Hints, магазин, жизни.
- Русская (и любая другая) локаль продукта.
- Режимы 4–7 букв.
- Чит-показ ответа до поражения.

---

## 15. Критерии приёмки (PM)

1. Загадывается английское слово из 5 букв; ровно 5 попыток.
2. Валидный ввод оценивается с корректной логикой повторов букв.
3. Невалидный ввод не тратит попытку и показывает EN-тост.
4. Клавиатура отражает статусы с приоритетом correct > present > absent.
5. Win/lose корректны, включая угадывание на 5-й попытке.
6. `New Game` полностью сбрасывает раунд и даёт новое слово.
7. UI покрывает playing / won / lost / toast / reveal / invalid shake.
8. Все пользовательские строки — на английском.
9. Edge cases §12.1–12.7 покрыты тестами или ручным чеклистом.
